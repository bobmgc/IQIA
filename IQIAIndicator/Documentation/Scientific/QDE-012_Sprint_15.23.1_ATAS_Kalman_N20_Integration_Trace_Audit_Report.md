3. CALL CHAIN
============================================================

```
ATAS (OnCalculate callback, per bar)
  -> IQIAIndicator.OnCalculate(bar, value)                                    [IQIAIndicator.cs:246]
       -> MarketContextBuilder.Build(bar, CurrentBar)                        [Core/MarketContextBuilder.cs:52]
            -> Core.MarketContext { Price, Volume, ... } (single-bar OHLCV snapshot, NO history list)
       -> IQIAIndicator.CreateScientificMarketContext(context, bar)          [IQIAIndicator.cs:720]
            -> builds `history`: List<decimal> of up to 500 Close prices,
               GetCandle(index).Close for index in [max(0,bar-499)..bar], ascending
            -> Engine.ScientificModels.Abstractions.MarketContext(Timestamp, CurrentBar, history, ...)
       -> SignalEngine.Process(scientificMarketContext, methodologySelection, trace) [Signal/SignalEngine.cs:48]
            -> ScientificModelRegistry.Resolve(methodologySelection) -> active models incl. KalmanFilterModel
            -> foreach model: ScientificModelContext { MarketContext, DecisionResult, MethodologySelection, ScientificResults }
            -> KalmanFilterModel.Evaluate(context)                           [MeanReversion/KalmanFilterModel.cs:53]
                 -> history = context.MarketContext.History (the exact 500-cap list built above, untouched)
                 -> windowStart = max(0, history.Count - 20); windowedHistory = history[windowStart..]
                 -> observations = windowedHistory as double[]
                 -> EstimateMeasurementNoise(observations) -> MeasurementNoise
                 -> Kalman recursion over `observations` -> FilterCovariance, KalmanGain
                 -> InnovationVariance = FilterCovariance + MeasurementNoise
                 -> InnovationStd = sqrt(InnovationVariance)
  -> ScientificDatasetRecord.From(...) [if EnableScientificDataset]           [Core/Calibration/ScientificDatasetRecord.cs:41]
       -> iterates result.Metrics generically -> "KalmanFilterModel.<key>" columns in the export
```

Two distinct `MarketContext` types exist in the codebase and this was the first ambiguity resolved:
`IQIAIndicator.Core.MarketContext` (`Core/MarketContext.cs`) is the raw, single-bar ATAS snapshot with
**no** history field at all — `MarketContextBuilder` only ever produces this one.
`IQIAIndicator.Engine.ScientificModels.Abstractions.MarketContext` (a `record` with the `History`
property `KalmanFilterModel` actually reads) is built separately, once per bar, by
`IQIAIndicator.CreateScientificMarketContext` — this is the single point where "HistoryLength" is
defined and populated.

5. WINDOW CONFIGURATION
============================================================

`private const int ObservationWindowSize = 20;` — `KalmanFilterModel.cs:51`. A `private const` on the
one class that reads it; not merely "a constant exists somewhere" — traced directly into the windowing
line two lines into `Evaluate()`:

```csharp
int windowStart = Math.Max(0, history.Count - ObservationWindowSize);      // KalmanFilterModel.cs:82
IReadOnlyList<decimal> windowedHistory = windowStart == 0 ? history : history.Skip(windowStart).ToList();
```

`observations = windowedHistory.Select(x => (double)x).ToArray()` feeds directly into
`EstimateMeasurementNoise(observations)`, `EstimateInitialVariance(observations)`, and the Kalman
recursion loop (`for (int i = 1; i < observations.Length; i++)`). **PROVEN**: no indirection, no
override, no dead code path.

13. CAPTURE 144244 EXPLANATION
============================================================

**Question**: why did the real ATAS capture `ScientificDataset_ES_M5_20260815_144244` report median
`InnovationStd ≈ 21.11011974333662` (1975 Kalman-eligible bars) when Sprint 15.22's offline validation
expected ≈4.13?

**Answer, proven two independent ways — BUILD_MISMATCH, not a data or model difference:**

**(a) Version-string traceability.** The DLL installed in ATAS at capture time
(`%APPDATA%\ATAS\Indicators\IQIAIndicator.dll`, `LastWriteTime` 2026-08-14 18:51:33, i.e. before the
capture's 2026-08-15 12:42-12:56 UTC collection window) carried `VersionInfo.ProductVersion =
"1.0.0+814a46eb62cdc10e6ed7b2be356dce177dc6d9c6"`. `814a46e` is an *ancestor* of HEAD
(`git merge-base --is-ancestor 814a46e be76c91` → true) that predates the Sprint 15.22 fix — confirmed
directly: `git show 814a46e:...KalmanFilterModel.cs` contains no `ObservationWindowSize`, no
`ObservationsUsed`, and computes `EstimateMeasurementNoise` over the **entire, unbounded**
`context.MarketContext.History` (`double[] observations = history.Select(...)`, no windowing at all —
the exact pre-15.22 defect the Sprint 15.21/15.22 reports describe). This also explains why
`ObservationsUsed` never appeared in the 144244 CSV header: that metric didn't exist yet in the DLL
that produced it.

**(b) Numerical reconstruction on the real captured data.** Using the 144244 capture's own OHLCV
export (`Close` price by `CurrentBar`) to rebuild the exact windows each formula would have used, for
8 sampled points spanning HistoryLength 98→400:

| CurrentBar | HistoryLength | MeasurementNoise (as captured, OLD/stale DLL) | Full-history population variance (OLD formula, independent recompute) | Last-20 population variance (NEW/HEAD formula, independent recompute) |
|---|---|---|---|---|
| 97 | 98 | 55.3534 | **55.3534** (exact match) | 5.0775 (no match) |
| 217 | 218 | 169.1640 | **169.1640** (exact match) | 61.1281 (no match) |
| 299 | 300 | 536.2456 | **536.2456** (exact match) | 4.5655 (no match) |
| 399 | 400 | 444.1717 | **444.1717** (exact match) | 11.8506 (no match) |

Every sampled captured value matches the OLD full-history formula exactly and diverges from the NEW
N=20 formula by 1-2 orders of magnitude. Extended to the full session: replaying all 1975
Kalman-eligible bars' real market data through the **current, unmodified HEAD** `KalmanFilterModel`
(same source file audited in Sections 5-8, called directly, not reimplemented) gives
`ObservationsUsed=20` throughout and **median InnovationStd = 3.3312** (mean 4.0936) — within the same
order of magnitude as, and directly comparable to, the Sprint 15.22 offline reference (~4.13),
obtained on an *entirely different* real ES/M5 session. The 6.3x gap between the captured 21.11 and
the HEAD-recomputed 3.33 on the *identical* market data is fully accounted for by the DLL version
difference alone — same input, same window boundaries, only the formula (windowed vs. unbounded)
differs.

**Classification: BUILD_MISMATCH.** DATA_DIFFERENCE is ruled out (identical price series used in both
computations). INTEGRATION_BUG / MODEL_BUG are ruled out (HEAD's own code, run on the same real data,
reproduces the expected offline order of magnitude). Per Phase 18's rule, this finding is reported,
not silently patched — the corrected DLL has been rebuilt and deployed (Section 14), and it is now up
to a genuinely new capture (Section 12) to confirm live.

- `KalmanFilterModel.DiagnosticsEnabled` defaults to `false`; when false, the `Evaluate()` diagnostic

  both additions are strictly additive and read-only with respect to the pre-existing computation

  lives entirely outside the git repository and outside ATAS's install path — nothing to clean up

- **Independently discovered, out-of-scope observation**: `ScientificDatasetCollector.Columns()`
  unions `Metrics.Keys` and `Categories.Keys` without cross-deduplication, and
  `ScientificDatasetRecord.AddMetric` unconditionally writes every metric into *both* dictionaries —
  so every scientific metric column (not just Kalman's) appears **twice** in the wide CSV's header
  (confirmed: 147-column header, ~60 distinct metric/category names duplicated). This is a pre-existing
  collector defect, unrelated to the N=20 question, and **not fixed here** per the RÈGLE ABSOLUE ("ne
  modifie pas le collecteur"). Worth a dedicated future ticket.
- **Parsing gotcha for future capture inspection**: some category fields (e.g.
  `Decision.RuleExplanation`) contain embedded newlines inside quoted CSV fields — naive
  line-based tools (`wc -l`, `awk -F,`, `head`) under/over-count records. The 144244 capture's raw
  file has 42527 physical lines for 3458 logical records. Use a quote-aware CSV reader (this audit
  used Python's `csv` module and a small hand-rolled quote-aware reader in C#, both included in the
  reproducibility harness).
